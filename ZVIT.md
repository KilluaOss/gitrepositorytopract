# Звіт з практичної роботи

**Тема:** Основи роботи з Git і GitHub.

**Мета роботи:** засвоїти основні команди Git, створення репозиторію, роботу з гілками, об'єднання змін та розв'язання конфліктів.

## Хід роботи

1. За допомогою `git init -b main` створено локальний репозиторій.
2. Командами `git add` і `git commit` збережено початкові файли.
3. Командою `git switch -c feature-description` створено нову гілку; у ній додано `feature.md`.
4. Після повернення до `main` виконано `git merge --no-ff feature-description`.
5. Створено файл `conflict.txt` та нову гілку `conflict-feature`.
6. У гілках `main` та `conflict-feature` змінено один і той самий рядок. Під час `git merge conflict-feature` виник реальний конфлікт.
7. Маркери конфлікту `<<<<<<<`, `=======`, `>>>>>>>` показали два варіанти. До `docs/conflict_before_resolution.txt` збережено стан перед виправленням.
8. Конфлікт розв'язано редагуванням `conflict.txt`: збережено зміст обох гілок. Результат додано через `git add` і зафіксовано командою `git commit`.

## Підтвердження виконання

- `docs/merge_output.txt` — вивід Git під час невдалого злиття.
- `docs/conflict_before_resolution.txt` — маркери реального конфлікту.
- `docs/status_during_conflict.txt` — стан репозиторію під час конфлікту.
- `docs/history_before_report_commit.txt` — граф комітів перед додаванням цього звіту.
- `conflict.txt` — успішно об'єднаний текст.

## Висновок

Під час практичної роботи створено Git-репозиторій, опрацьовано основні команди, гілки, коміти та об'єднання змін. На реальному прикладі продемонстровано появу і розв'язання конфлікту під час злиття гілок.

**Публікація на GitHub:** перевірте, чи завершилось завантаження репозиторію; якщо ні — скористайтеся інструкцією в `README.md`.
